## Which channel do I use?

### 💬 Discussions — for questions

Use [Discussions](https://github.com/RISHII7/E-commerce/discussions) when you want to **ask**
something:

- "How do I configure X?"
- "Is this the intended way to do Y?"
- "Has anyone run this on Z?"
- "I have an idea, but it is not a concrete proposal yet."
- "I am not sure whether what I am seeing is a bug."

**Nothing here is too basic.** A question that was hard to find the answer to is usually a
documentation gap, and asking it helps the next person as much as it helps you.

### 🐛 Issues — for defects and defined work

Use the [issue tracker](https://github.com/RISHII7/E-commerce/issues/new/choose) when you can point
at something specific and actionable:

| Template | For |
| :--- | :--- |
| 🐛 **Bug report** | Something is broken. Include reproduction steps, expected versus actual behaviour, and your environment. |
| ✨ **Feature request** | A new capability. Describe **the problem first**, then your proposed solution. |
| 🔧 **Task** | Internal engineering work — refactors, upgrades, tooling, technical debt. |
| 📚 **Documentation** | Documentation that is wrong, outdated, missing or unclear. |

Blank issues are disabled on purpose. The templates exist so a report arrives with the information
needed to act on it, rather than starting a round of follow-up questions.

### 🔒 Security — always private

Vulnerabilities go through
[GitHub Private Vulnerability Reporting](https://github.com/RISHII7/E-commerce/security/advisories/new),
never a public issue. Full policy in [SECURITY.md](SECURITY.md).

## Helping us help you

The difference between a question that gets answered quickly and one that stalls is almost always the
level of detail. Please include:

1. **What you were trying to do** — the goal, not only the step that failed.
2. **What you did** — exact commands or requests.
3. **What you expected to happen.**
4. **What actually happened** — the exact error, not a paraphrase.
5. **Your environment** — output of `java -version`, your OS, and the version or commit you are on.
6. **What you already tried.** This saves everyone from suggesting it again.

> [!TIP]
> A **minimal reproducible example** is the single most useful thing you can provide. Strip the
> problem down to the smallest thing that still fails. Very often you will find the cause yourself
> while doing it — and if not, whoever helps you starts from a running reproduction instead of a
> description.

## Response times

This is an open-source project maintained in spare time. There is no support contract and no
guaranteed response window.

In practice:

| | Typical |
| :--- | :--- |
| **Security reports** | Highest priority — see [SECURITY.md](SECURITY.md) for target timeframes |
| **Bug reports with clear reproduction steps** | Handled next |
| **Feature requests** | Read and considered; implementation depends on the roadmap |
| **Questions in Discussions** | Answered as time allows |

A well-written report with reproduction steps will always be picked up before a vague one. That is
not a rule anyone made — it is simply that one can be acted on immediately and the other cannot.

## Please do not

- ❌ Open a public issue for a security vulnerability
- ❌ Comment "any update?" on an issue within a day or two of opening it
- ❌ Open duplicate issues — search first, and add to the existing thread instead
- ❌ Contact the maintainer privately for general support; use Discussions so the answer helps others
- ❌ Post credentials, tokens or personal data in an issue, a discussion or a log paste

## Want to help?

The fastest route to a fix is often to write it yourself. [CONTRIBUTING.md](CONTRIBUTING.md) walks
through the whole process, and issues labelled
[`good first issue`](https://github.com/RISHII7/E-commerce/issues?q=is%3Aissue+is%3Aopen+label%3A%22good+first+issue%22)
are deliberately scoped as gentle entry points.
